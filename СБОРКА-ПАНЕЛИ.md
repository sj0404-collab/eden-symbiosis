# Сборка панели в GitHub Actions

Панель без эмулятора и без заглушек, страницы внутри APK.

## Команды

Локальной сборки не будет: в песочнице 2 ГБ RAM, а Android SDK и Gradle
стираются между сессиями. Собирает GitHub — там 16 ГБ, 4 ядра и всё
предустановлено.

```bash
cd <ваша копия репо>

# если репозиторий уже переименован:
git remote set-url origin https://github.com/sj0404-collab/symbiosis.git

git add -A
git commit -m "Panel APK: self-contained, no emulator, no stubs"
git push
```

Затем: **Actions → Panel APK → Run workflow**. Около пяти минут.

Результат:
- артефакт `symbiosis-panel-apk`;
- постоянная ссылка `releases/download/panel-latest/symbiosis-panel.apk`;
- зеркало на gofile — ссылка и MD5 печатаются в сводке запуска.

Если сборка нужна без gofile, в диалоге Run workflow снимите галочку
`upload_to_gofile`.

## Что сборка проверяет

APK, который собрался, ещё ничего не доказывает: пустая папка `assets/`
даёт совершенно валидный файл, который на телефоне показывает «страница не
входит в сборку». Поэтому workflow вскрывает готовый APK и проверяет:

| Проверка | Зачем |
|---|---|
| все шесть страниц лежат в `assets/panel/` | иначе на телефоне 404 вместо панели |
| `index.html` > 20 КБ и содержит `api.github.com` | это настоящая панель, а не заглушка и не обрезок |
| упакованный `index.html` побайтово равен `docs/index.html` | APK не отстал от репозитория |
| **ни одного `lib/*.so`** | эмулятор не просочился в сборку |
| **нет класса `CookieManager2`** | стабы не скомпилировались в APK |
| в dex есть `MainActivity` и `PanelAssets` | ни один класс не потерялся |
| в оболочке не осталось загрузки с Pages | панель действительно локальная |

Про две средние строки подробнее, потому что это ровно то, что просили.

**Без эмулятора.** Эмулятор — это 21 МБ и `libkenjinxjni.so`,
`libsymbiosis_kenji.so` и ещё десяток нативных библиотек. Панель — два класса
Kotlin и ни одной `.so`. Проверка отбраковывает APK, если внутри найдётся хоть
одна нативная библиотека. Прогнал её на реальном `Symbiosis.apk` из релизов:
эмулятор она отбраковывает.

**Без заглушек.** `panel-app/stubs/` нужен только для быстрой проверки типов
без Android SDK — эти файлы объявляют `package android.webkit` и подобные, и
попади они в сборку, они перекрыли бы настоящий фреймворк. К Gradle они не
подключены, но проверять надо результат, а не намерение.

Искать в dex слово `android.webkit` бессмысленно — настоящий фреймворк
упоминается в любой сборке. Поэтому канарейкой служит `CookieManager2`: класс,
выдуманный для стаба, которого нет в Android. Есть он в dex — значит стабы
скомпилировались. Проверил на двух искусственных dex: с канарейкой ловит, без
неё пропускает.

## Почему сборка не локальная

Пробовал: поставил JDK 17, Android SDK 34, Gradle 8.7 — примерно 500 МБ.
Упёрся в то, что `/tmp` здесь всего 1 ГБ (SDK не влез), а после переноса на
диск — в 2 ГБ RAM на Gradle и компилятор Kotlin одновременно. Плюс всё
установленное стирается между сессиями, так что каждый прогон начинался бы
заново. На раннере это штатная сборка на пять минут.

## Проверить перед пушем

```bash
node tests/t_chat_replies.js
node tests/t_chat_history.js
node tests/t_chat_live.js
kotlinc tests/PanelAssetsTest.kt -include-runtime -d /tmp/t.jar && java -jar /tmp/t.jar
```

Первые три — про чат, последний — 34 проверки маршрутизации панели: что
`api.github.com` уходит в сеть, а страницы отдаются из APK. В CI они
запускаются сами (`tests/*.js` подхватывает `tools/run_tests.sh`).
