# Переименование в `symbiosis` и сборка панели

## Что уже сделано в коде

Все 23 упоминания `eden-symbiosis` заменены на `symbiosis` — в workflow, панели,
README и в ссылках эмулятора. Эмулятор при этом **не тронут**: изменились только
адреса, ни одной строки логики.

Панель стала отдельным самодостаточным приложением: страницы упакованы внутрь APK.

## Что нужно нажать вам

У меня в песочнице нет ни `gh`, ни токена, поэтому два шага — за вами.

**1. Переименовать репозиторий**

Settings → вверху поле Repository name → `symbiosis` → Rename.

GitHub сам поставит редирект со старого адреса, так что уже сделанные `git clone`
и ссылки не отвалятся. Но redirect пропадает, если кто-то потом займёт старое имя,
поэтому адреса в коде я всё равно обновил.

**2. Запушить эти изменения**

```bash
cd <ваша копия репо>
git remote set-url origin https://github.com/sj0404-collab/symbiosis.git
git add -A
git commit -m "Rename to symbiosis; panel APK is now self-contained"
git push
```

**3. Собрать APK**

Actions → **Panel APK** → Run workflow. Около пяти минут.
Готовый файл: артефакт `symbiosis-panel-apk` и постоянная ссылка
`releases/download/panel-latest/symbiosis-panel.apk`.

## Что изменилось в приложении панели

Было: WebView, который грузил страницу с GitHub Pages. Без интернета — экран
«Повторить», то есть приложение бесполезно ровно тогда, когда телефон офлайн.

Стало: страницы (`index.html`, `library.html`, `desks.html`, `panel.html`,
`icon.svg`, манифест) копируются Gradle из `docs/` в `assets/` и отдаются
из APK. Панель открывается без сети. Интернет нужен только для того, ради
чего панель и существует — GitHub API, запуск workflow, туннель сессии.

**Почему не `file://`.** Панель хранит токен в `localStorage` и ходит на
`api.github.com`. У документа с `file://` origin непрозрачный: localStorage
между запусками теряется, а кросс-доменные запросы блокируются. Поэтому
страницы отдаются через перехватчик под обычным https-origin
(`panel.symbiosis.local`) — в сеть по этому адресу ничего не уходит,
но браузерная модель безопасности считает его нормальным сайтом.

**Цена решения.** Правка `docs/` больше не долетает до установленного
приложения сама — нужно пересобрать и переустановить APK. Поэтому workflow
теперь запускается и на изменения `docs/`, а в сводке печатается MD5:
видно, что установленная сборка отстала.

## Что проверяется при сборке

Раньше проверялось только то, что APK вообще собрался. Пустая папка `assets/`
даёт совершенно валидный APK, который на телефоне показывает «страница не
входит в сборку» — поэтому теперь workflow заглядывает внутрь готового файла:

- каждая из шести страниц реально лежит в `assets/panel/`;
- `index.html` больше 20 КБ и содержит `api.github.com` — то есть это настоящая
  панель, а не заглушка и не обрезанная копия;
- упакованный `index.html` **побайтово совпадает** с `docs/index.html`;
- в оболочке не осталось загрузки панели из сети.

Плюс быстрая проверка типов (`kotlinc` со стабами, ~10 секунд) — она ловит
ошибки до четырёхминутного Gradle.

## Тесты

```bash
node tests/t_chat_replies.js     # чат: 40 проверок по исходникам
node tests/t_chat_history.js     # чат: 24 раунда против строгого стенда
node tests/t_chat_live.js        # чат: 7 сценариев через реальный HTTP API
kotlinc tests/PanelAssetsTest.kt -include-runtime -d /tmp/t.jar && java -jar /tmp/t.jar
```

`PanelAssetsTest` — 34 проверки маршрутизации: что `api.github.com` уходит
в сеть (иначе панель показала бы свой HTML вместо ответа API), что страницы
отдаются из APK, что `..` и вложенные пути отклоняются. Он же сверяет себя
с реальным `PanelAssets.kt`, чтобы копия логики не разошлась с кодом.

Отдельно поправил гонку портов: два набора тестов брали пересекающиеся
диапазоны, а агент при занятом порте молча переходит на соседний — тест потом
стучался не туда и падал через раз. Теперь порт запрашивается у системы.
