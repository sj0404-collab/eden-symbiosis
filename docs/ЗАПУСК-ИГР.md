# Почему игра не появляется в списке

Записано по итогам разбора, который занял целый день. Симптом был такой:
файлы в папке видны, размеры правильные, панель показывает «Ключи ✓» и
«Прошивка ✓», а список игр пуст и иконок нет.

## Ответ: старые ключи

Помогла замена **обоих** файлов ключей на версию, соответствующую прошивке:

```
/Download/ed/Eden/files/keys/prod.keys
/Download/ed/Eden/files/keys/title.keys
```

После этого игра запустилась сразу — 60 FPS на Mali-G57 MC2 / MT6789.

## Почему панель показывала «Ключи ✓»

Это не ложь, но и не весь ответ. Галочка приходит от самого эмулятора:

```cpp
inline bool AreKeysPresent() {
    return !Core::Crypto::KeyManager::Instance().BaseDeriveNecessary();
}
```

`BaseDeriveNecessary()` проверяет только **базовые** ключи: header_key,
master, key_area, titlekek. Их наличия достаточно, чтобы вернуть «да».

Но каждая игра в `.nsp` зашифрована ещё и **своим** ключом — titlekey. Он
берётся из `title.keys` или из билета `.tik` внутри самого файла. Про него
`AreKeysPresent()` не знает ничего.

Отсюда и получалось: базовые ключи на месте → галочка стоит → а игра не
расшифровывается, потому что не хватает ключа именно к ней. Или, как
оказалось в этом случае, ключи были просто **устаревшие** — от прошивки
старее той, что стоит.

## Что не было причиной

Проверено и отброшено по дороге:

| подозрение | почему отпало |
|---|---|
| размер файла | фильтра по размеру в патче нет вообще; 283 МБ — нормальный размер для инди |
| это DLC, а не игра | TitleID `...E000` + `[v0]` — базовая игра, всё верно |
| глубина сканирования | сборка с родной глубиной 3 вела себя так же |
| флейвор legacy/mainline | контрольная сборка без патча работала на legacy |
| строки, разметка, интерфейс | сборка со всем интерфейсом и без папок работала |

## Как понять это быстрее в следующий раз

По TitleID в имени файла, последние три знака:

| окончание | что это | запускается? |
|---|---|---|
| `...000` | базовая игра | да |
| `...800` | обновление | нет, ставится поверх игры |
| прочее | DLC | нет |

Пример из этого разбора:

```
Blade Chimera [01007FC01CF4E000][v0] (0.28 GB).nsp        игра
Blade Chimera [01007FC01CF4E800][v393216] (0.17 GB).nsp   обновление
```

Если базовая игра есть, а в списке её нет — дело почти всегда в ключах, и
`title.keys` подозревать нужно раньше, чем `prod.keys`.

## Что теперь делает панель

`SetupStatus.whyNotGames()` больше не гадает по размеру, а зовёт
`NativeSymbiosis.diagnoseRom()` — та проходит ровно тот же путь, что и
запуск игры, и возвращает настоящий код отказа загрузчика:

- `no_title_key` — нет ключа именно для этой игры
- `update_only` — внутри нет базовой игры, это обновление
- `corrupt` — файл повреждён или скачан не полностью
- `bad_keys` — prod.keys от другой прошивки

Так следующий такой случай будет виден с первого взгляда, а не через день
перебора гипотез.
